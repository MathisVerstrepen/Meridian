# Agent profiles and Teams

Settings → Agent provides My Agents, Bookmarked, Forked, Recently Used, Team Agents, Marketplace, and Drafts. Create a profile or start from one of eight presets. Profiles have a unique private-library handle, identity, description, category/tags, ordered prompt layers, model overrides, and six tool permissions. Save creates a new version; restoring an earlier version creates another version. Public listings require an active profile. Archived profiles cannot execute. Delete is available only after archiving and when no graph, Team, or execution references the profile.

A Team is a private, ordered pool of your active profiles. Order affects presentation. It does not schedule execution. Configure an Agent node with an independent main model and exactly one private Team. Every account has a permanent Default Team, automatically selected for new Agent nodes. Newly created, imported, duplicated, and forked Agents are added to it automatically; editing an existing Agent does not re-add it after you have removed it. Existing accounts receive a Default Team containing their current profiles. You can manage ordered membership in Settings. Only active members are eligible to execute. The main model uses graph settings and its own node tool selection, like Text to Text. The selected Team is the entire authorized subagent pool. Agent nodes cannot select individual profiles. Selecting a Team never executes its members automatically. Using subagents requires an OpenRouter main model which advertises tool calling. Choose a supported main model or a Team without active members if capability validation fails.

The main model receives eligible member identities and descriptions and the internal `delegate_agents` function. Its `calls` array batches independent tasks for parallel execution. Subsequent calls can depend on earlier results. Subagents cannot delegate. Default limits are four concurrent subagents, sixteen total calls, six delegation rounds, and ten minutes of cumulative active execution. Successful parallel sibling results survive another member's failure. The main model receives subagent results as intermediate tool outputs and formulates its own final answer. Only main-model output streams into the node and chat reply. Subagent output remains attributed in execution details. Each subagent run retains its profile identity/version, task, status, tools, results, errors, usage, and timestamps.

Subagents can use only tools in their executing profile's current allowlist. The main model uses the node’s manual tool selection or Auto Tool Selection, configured with the same controls as Text to Text. Automatic selection chooses supported tools for the current task, records the resolved policy, and rechecks current capabilities/settings on continuation. It never inherits a Team member’s tools. Web search requires both web search and link extraction permission; dependency handling never adds permission. Image generation governs image editing and current image/video generation. Delegation is internal orchestration, separate from these permissions. A Team never grants the main model its members' tools.

A single leading `@team-handle` in graph chat selects that private Team on the created Agent node while preserving the main model. The Default Team always uses `@default`. Unknown or multiple leading mentions are rejected before graph mutation. Autocomplete shows your Teams. Agent profile handles do not select a pool. Without a mention, the main model uses the configured pool. With an empty pool it responds normally. Marketplace profiles must be forked into your library before use. Bookmarks and one mutable 1–5 rating are authenticated. Only an administrator may set “Verified by Meridian”; editing a verified profile clears verification.

Ask User pauses the attributed run. Answering resumes its execution tree after access, lifecycle, current permissions, Team authorization, model capability, and remaining budget checks. Configuration changes that invalidate the paused execution require running the node again. Completed generation snapshots retain the main-model and pool configuration and inspectable run results; restoring a snapshot does not authorize future execution.

Existing graph context, attachments, global prompts, and provider context limits continue to apply. Profiles do not offer configurable context-source rules.

## Offline cutover

This release cannot run alongside older API/UI workers. Back up PostgreSQL, Neo4j, and Redis, then stop all API/UI workers and schedulers before proceeding. Apply the additive Alembic revisions through `c7b9e12d6a30`. Run `make agents-cutover ARGS=--maintenance-confirmed` with the same rendered local environment, or invoke `PYTHONPATH=app venv/bin/python scripts/cutover_agents.py --maintenance-confirmed` from `api/` inside the deployment environment.

The API image includes the command at `/app/scripts/cutover_agents.py`. For a production Compose deployment, while application workers remain stopped, run these commands from the repository root using the newly built API image:

```sh
docker compose --env-file docker/env/.env.prod -f docker/docker-compose.prod.yml run --rm --no-deps api alembic upgrade head
docker compose --env-file docker/env/.env.prod -f docker/docker-compose.prod.yml run --rm --no-deps -e PYTHONPATH=/app api python /app/scripts/cutover_agents.py --maintenance-confirmed
```

The explicit command checks all three stores and the schema revision before conversion. It converts existing Routing nodes and historical snapshots to unconfigured Agent nodes, preserves reply text and active history identity, discards all old model/route/tool/usage configuration, removes old settings, reconciles Neo4j types, and invalidates pending Routing continuations. It never creates profiles or Teams from Route settings. Rerun the command while workers remain stopped to finish an interrupted cross-store conversion; each stage is idempotent. Start the new application only after verification succeeds. Converted Routing nodes require a main model selection. Earlier Agent nodes with a primary-profile reference are converted once: the account default becomes the main model, individual selections are discarded, and missing Teams are replaced with the account’s Default Team. Existing valid Team selections survive. Replies and historical execution details survive; profile tools do not become main-model tools. Incompatible pending Agent continuations are invalidated too.

The migrations add persistence and backfill default Teams and membership. It does not run the destructive conversion at startup.
